# Autocheck — интеграция с выгрузками 1С

Микросервис интеграции с партнёрскими автосалонами: забирает файлы выгрузки 1С,
разбирает их, складывает автомобили в базу **без дублей по VIN** и показывает
результат на веб-странице.

Загрузка запускается двумя способами — **по расписанию** и **принудительно по
запросу**. Оба триггера вызывают один и тот же сервис загрузки: логика разбора
и записи не продублирована.

## Быстрый старт

Нужен только Docker.

```bash
git clone <URL репозитория>
cd autocheck
docker compose up --build
```

Готово:

| Что | Адрес |
|---|---|
| Веб-интерфейс | http://localhost:3000 |
| API | http://localhost:8000 |
| Документация API (Swagger) | http://localhost:8000/docs |

При старте контейнер сразу загружает файлы из `data/feeds`, поэтому таблица не
бывает пустой. В комплекте два файла выгрузки: `feed_day1.csv` и `feed_day2.csv`,
где 75 VIN повторяются — это и демонстрирует upsert (повторы обновляются,
дубли не создаются).

Остановить и удалить данные:

```bash
docker compose down -v
```

## Как проверить, что всё работает

```bash
# состояние сервиса и последняя загрузка
curl localhost:8000/api/stats

# дублей нет: количество машин равно количеству уникальных VIN
curl "localhost:8000/api/vehicles?limit=500" \
  | python3 -c "import json,sys; d=json.load(sys.stdin); v=[x['vin'] for x in d['items']]; print(len(v), len(set(v)))"
```

**Принудительная загрузка (второй триггер):**

```bash
curl -X POST localhost:8000/api/ingest
```

Сразу после старта этот вызов вернёт нули — и это правильно: файлы из каталога
уже загружены при старте, а обход пропускает необработанное. Чтобы увидеть работу
на тех же файлах, добавьте `?force=true`:

```bash
curl -X POST "localhost:8000/api/ingest?force=true"   # переобрабатывает всё
```

**Загрузка по расписанию (первый триггер).** Положите новый CSV в `data/feeds` —
ближайший тик (по умолчанию 60 секунд) подхватит только его:

```bash
cp data/feeds/feed_day1.csv data/feeds/feed_day3.csv
docker compose logs -f backend | grep "scheduled ingest"
# scheduled ingest feed_day3.csv: created=5 updated=101 skipped=14 in 38ms
```

## Локальная разработка (без Docker)

**Бэкенд** (Python 3.11+):

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
uvicorn app.main:app --reload
```

**Фронтенд** (Node 20+):

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173, /api проксируется на :8000
```

**Тесты:**

```bash
cd backend && pytest                    # 77 тестов
pytest --cov=app --cov-report=term-missing
```

## Как это устроено

```
                    ┌──────────────────────┐
 по расписанию ───► │                      │
 (APScheduler)      │  services/ingest.py  │ ──► SQLite
                    │                      │     ON CONFLICT(vin) DO UPDATE
 POST /api/ingest ► │  единственный путь   │
 (вебхук/файл)      └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │  parsers/csv_1c.py   │  чистый: bytes → записи + ошибки
                    └──────────────────────┘
```

Ключевые решения:

- **Один путь загрузки.** Планировщик и вебхук — тонкие обёртки над
  `ingest_bytes`. Разбор не дублируется под каждый триггер.
- **Парсер чистый.** Принимает байты, возвращает проверенные записи и список
  отбраковок, к базе не обращается. Поэтому тесты парсера не требуют БД,
  а тесты upsert — файла.
- **Отсутствие дублей обеспечивает база,** а не код: на `vin` стоит `UNIQUE`,
  запись идёт через `INSERT ... ON CONFLICT(vin) DO UPDATE`. Приложенческая
  проверка «есть ли уже такой VIN» здесь гонялась бы с параллельной загрузкой.
- **`first_seen_at` не перезаписывается** при обновлении: это дата, когда
  автомобиль впервые попал к нам.
- **Битая строка не роняет файл.** Отбраковки собираются с номером строки
  и причиной, попадают в историю загрузок и видны в интерфейсе.
- **Обход каталога инкрементальный:** файлы сортируются по времени изменения
  (не по имени — `feed_day10.csv` сортируется раньше `feed_day2.csv`), уже
  обработанные пропускаются по тройке «имя + mtime + размер».
- **Причины отбраковки — машинные коды,** а текст собирается на клиенте, чтобы
  их можно было показать и по-русски, и по-казахски.

## Формат выгрузки

Генератор воспроизводит особенности реальной выгрузки 1С: кодировка
**windows-1251**, разделитель `;`, кириллические заголовки, запятая как
десятичный разделитель, неразрывный пробел в разрядах, даты `ДД.ММ.ГГГГ`,
валидная контрольная цифра VIN, ~6% «грязных» строк.

```
VIN;Марка;Модель;ГодВыпуска;Пробег;Цена;Цвет;ТипКузова;КПП;ОбъемДвигателя;Дефекты;Салон;Город;ДатаВыгрузки
```

Парсер принимает и UTF-8, и windows-1251, и файлы с BOM.

Сгенерировать свои данные:

```bash
python scripts/generate_feed.py --rows 120 --out data/feeds/feed_day1.csv
python scripts/generate_feed.py --rows 130 --out data/feeds/feed_day2.csv \
    --base data/feeds/feed_day1.csv --carry-over 0.7
```

`--base` переносит часть VIN из первого файла во второй с увеличенным пробегом
и сниженной ценой — материал для проверки upsert.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/ingest` | Принудительная загрузка. Без файла — обход каталога, с файлом (`multipart/form-data`, поле `file`) — загрузка этого файла. `?force=true` переобрабатывает уже обработанные файлы |
| `GET` | `/api/vehicles` | Список машин: `search`, `brand`, `sort`, `order`, `limit`, `offset` |
| `GET` | `/api/brands` | Список марок для фильтра |
| `GET` | `/api/runs` | История загрузок, свежие первыми |
| `GET` | `/api/stats` | Сводка и последняя загрузка |
| `GET` | `/api/health` | Проверка живости |

## Настройки

Все через переменные окружения с префиксом `AUTOCHECK_`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AUTOCHECK_DATABASE_URL` | `sqlite:///./data/autocheck.db` | Подключение к БД |
| `AUTOCHECK_FEED_DIR` | `./data/feeds` | Каталог, за которым следит планировщик |
| `AUTOCHECK_INGEST_INTERVAL_SECONDS` | `60` | Интервал загрузки; `0` отключает планировщик |
| `AUTOCHECK_CORS_ORIGINS` | `http://localhost:5173,http://localhost:3000` | Разрешённые источники |

## Что осознанно не сделано

Ограничения MVP, названные явно, чтобы не выглядеть недосмотром:

- **Нет миграций.** Схема создаётся через `create_all`. При обновлении версии
  со сменой схемы удалите том: `docker compose down -v`. Для продакшена нужен
  Alembic.
- **Гонка при записи файла.** Если партнёр пишет `feed.csv` в момент обхода
  каталога, файл может быть прочитан наполовину. Промышленное решение —
  соглашение об атомарном переименовании (`.tmp` → `.csv`); сейчас не реализовано.
- **Нет снятия с публикации.** Машины, пропавшие из выгрузки, остаются в базе.
  Поле `last_seen_at` для этого есть, логики нет.
- **Нет аутентификации.** Сервис рассчитан на закрытый контур.
- **Одна база SQLite.** Достаточно для MVP; при росте нагрузки на запись
  меняется на PostgreSQL (`AUTOCHECK_DATABASE_URL`).
- **Содержимое выгрузки не переводится** (тип кузова, цвет, дефекты) — это
  данные партнёра, а не интерфейс.
